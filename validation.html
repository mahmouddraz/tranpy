Validation of the 0.2 refactor

This page records how the refactored package was checked against the previous code, which defects were found, and every place where results intentionally differ. It is the reference for anyone comparing numbers produced before and after the refactor.

Method

  1. Starting point. main merged with feature/md/prepare4pypi (commit 7d9c185), i.e. the last state of the 0.1.x code including the temporal-feature work.

  2. Old test suite. 156 tests: 151 passed, 5 failed (see Old test failures).

  3. Golden baseline. A script outside the repository loaded every bundled dataset, made a fixed stratified split (seed 42), trained every classifier (seed 0) behind a StandardScaler fitted on the training rows, and recorded dataset checksums, split indices, accuracy/F1/ROC-AUC/confusion matrix, test-set probabilities of every model, SHAP values, LIME weights, surrogate rankings, the event labels and fault timings, trajectory features for five windows, and early-prediction results.

  4. Determinism. Two runs of the baseline were bit-identical for everything except the old mock engine (see D12). TensorFlow runs used op determinism.

  5. Corrected reference. The old code was not taken as ground truth. A separate worktree of the old code received only bug fixes (stratified split, LightGBM argument bug, seeded LIME and SHAP, LIME global explanation on test data, surrogate fidelity as agreement, NaN instead of 0 for undefined AUC). Its golden output is the reference for the new code.

  6. Comparison. The same golden script, written against the new API, was run with identical library versions (scikit-learn 1.9.1, NumPy 2.5.4, pandas 3.1.0, SHAP 0.54.1, TensorFlow 2.21.0, XGBoost 3.4.1, LightGBM 4.7.0, Python 3.12, macOS arm64).

D9

A

fault clearing time detected from voltage recovery and used as the start of the early-prediction window

for collapsing (unstable) events “clearing” is found late: median detected fault duration on New England 0.25 s (stable) vs 0.27 s with 95th percentile 2.6 s (unstable); on the 9-bus system the out-of-step flag is set before the detected clearing in most unstable events (median onset 0.23 s before). Windows “after clearing” therefore already contain the outcome; early-prediction accuracy is optimistic

windows need an explicit reference: fault_start (causal), fault_clear (reproduces old behaviour, documented as non-causal) or absolute. Simulated datasets store the true clearing time

Intentional deviations (summary)

  • D2 scaling inside pipelines, D9 window reference, D10 recovery time, D11 NaN AUC, D5 QDA regularisation, D12 new mock engine. Every other output is identical to the corrected reference.

Observations kept for continuity (open decisions)

  • sys_max_relative_angle is mathematically identical to sys_angle_spread_max (largest pairwise difference = max minus min). Kept so feature sets stay comparable.

  • find_knee_point uses index-based derivatives, i.e. treats the windows as equally spaced. Kept; with derivatives over the window length the knee moves to longer windows.

  • The snapshot datasets contain duplicated rows (New England 25, 9-bus 22) that can fall on both sides of a split. ExperimentSpec(group_duplicates=True) keeps them together; the default is unchanged.

  • SVC(probability=True) is deprecated in scikit-learn 1.9 and removed in 1.11; the dependency is capped below 1.11 to keep SVM results identical.

How results stay pinned

  • tests/regression/test_snapshot.py checks the seeded metrics of every model/dataset combination against tests/snapshots/metrics.json. After an intended change run uv run python -m tests.update_snapshot and state the reason in the commit message.

  • Bundled and downloadable data files are pinned by SHA-256 in src/tranpy/resources/registry.json; .npz files are written byte-for-byte reproducibly, so re-running scripts/convert_legacy_data.py reproduces the checksums.

With 500 events the tree ensembles on trajectory features are best at short windows; sequence networks catch up from about 0.4 s. The networks were not tuned and are data-limited at this sample size; conclusions about them need the full event sets.

Effect of D9 on real data. The same random forest with windows measured from the detected clearing instead of inception reaches 0.998 (9-bus) and 0.990 (39-bus) already at 0.05 s, against 0.966 and 0.980 from inception: clearing-based windows overstate early accuracy, most strongly on the 9-bus system at short windows.

Snapshot feature names

The legacy snapshot columns were named F_0 ... F_n. Their meaning was recovered from the data:

  • The first n_buses columns (9-bus: 9, 39-bus: 39) are bus voltage magnitudes in p.u., in bus order 1..n, at fault inception. Evidence: their per-bus means correlate with the voltages of the recorded event trajectories at the detected fault inception with r = 0.98 (9-bus) and r = 0.995 (39-bus); at fault clearing the correlation drops to 0.79 and 0.53. They are named Bus k voltage (p.u.).

  • The remaining columns (8 and 38) are bus voltage angles in degrees of all buses but one. The omitted (reference) bus and the order could not be determined: matching their statistics against the recorded angles relative to each candidate reference bus does not single out one bus (39-bus: best candidate Bus 31, the usual reference generator of the PowerFactory model; 9-bus: Buses 7, 9 and 8 score almost equally). They are named Angle k (deg, bus unknown) until the original generation script confirms the mapping.

The values, labels and order of the data are unchanged; the regression snapshot is unaffected.
