Architecture

TranPy has two layers in one distribution (tranpy-ai):

tranpy        power-system layer: systems, vocabulary, datasets, trajectory features,
              early prediction, simulation engines, pretrained models, CLI, plots
   |
   v  (one-way dependency, enforced by tests/test_import_boundaries.py)
tranpy_core   generic layer: labelled tabular / time-series data -> features ->
              models -> evaluation -> explanation, experiment runner

tranpy_core knows nothing about buses or generators; it could serve any labelled time-series or tabular classification problem (see notebook 06). Optional backends (SHAP, LIME, DALEX, TensorFlow, XGBoost, LightGBM, matplotlib, skops, PowerFactory) are imported only inside the functions that need them.

Data flow

PowerFactory / MockEngine --generate_events--> SignalDataset (.npz)
                                                   |
                         TrajectoryFeatures(window_s, reference)
                                                   v
bundled snapshots ----------------------------> TabularDataset
                                                   |
                         train_test_split / kfold_splits (seeded, stratified)
                                                   v
                         make_pipeline(name) = StandardScaler -> estimator
                                                   |
                         evaluate / cross_validate / run_experiment
                                                   v
                         explain_shap / explain_lime / fit_surrogate

Leakage rules built into this flow: feature extraction is stateless and only sees data up to the window end; anything fitted from data (scaling, models) lives in a pipeline and is refitted on each training fold; label-defining channels (s:outofstep) are removed when events are loaded.

Extension points

  • Model: register_model(ModelSpec(name="my_model", estimator="pkg.module.Class", defaults={...}, seed_param="random_state", extra="...")). Any scikit-learn compatible class works; implement __init__ storing parameters only.

  • Feature extractor: any object with transform(SignalDataset) -> TabularDataset (tranpy_core.features.SignalFeatureExtractor). Build it from tranpy_core.features.segments to stay vectorised.

  • Dataset: write a TabularDataset/SignalDataset with save_tabular/save_signals, then add an entry with filename, SHA-256 and URL to src/tranpy/resources/registry.json.

  • Explainer: a function (model, X, *, background, seed) -> Explanation.

  • Simulation engine: implement the SimulationEngine protocol (system, n_lines, n_loads, simulation_time_s, simulate(scenarios) -> list[SimulationResult]); generate_events then works unchanged.

Data hosting

See data.md: bundled snapshots, sharded event datasets streamed from GitHub release assets, lossless compact storage, checksums everywhere.
