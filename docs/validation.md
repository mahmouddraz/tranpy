# Validation of the 0.2 refactor

This page records how the refactored package was checked against the previous code,
which defects were found, and every place where results intentionally differ. It is the
reference for anyone comparing numbers produced before and after the refactor.

## Method

1. **Starting point.** `main` merged with `feature/md/prepare4pypi` (commit `7d9c185`),
   i.e. the last state of the 0.1.x code including the temporal-feature work.
2. **Old test suite.** 156 tests: 151 passed, 5 failed (see [Old test failures](#old-test-failures)).
3. **Golden baseline.** A script outside the repository loaded every bundled dataset,
   made a fixed stratified split (seed 42), trained every classifier (seed 0) behind a
   StandardScaler fitted on the training rows, and recorded dataset checksums, split
   indices, accuracy/F1/ROC-AUC/confusion matrix, test-set probabilities of every model,
   SHAP values, LIME weights, surrogate rankings, the event labels and fault timings,
   trajectory features for five windows, and early-prediction results.
4. **Determinism.** Two runs of the baseline were bit-identical for everything except
   the old mock engine (see D12). TensorFlow runs used op determinism.
5. **Corrected reference.** The old code was not taken as ground truth. A separate
   worktree of the old code received *only* bug fixes (stratified split, LightGBM
   argument bug, seeded LIME and SHAP, LIME global explanation on test data, surrogate
   fidelity as agreement, NaN instead of 0 for undefined AUC). Its golden output is the
   reference for the new code.
6. **Comparison.** The same golden script, written against the new API, was run with
   identical library versions (scikit-learn 1.9.1, NumPy 2.5.4, pandas 3.1.0, SHAP 0.54.1,
   TensorFlow 2.21.0, XGBoost 3.4.1, LightGBM 4.7.0, Python 3.12, macOS arm64).

## Equivalence with the corrected reference

| Output | Result |
|---|---|
| Dataset contents (features, labels, order) | identical (checksums equal) |
| Train/test split indices | identical |
| Test probabilities / scores, 18 classical models x 2 datasets | **bit-identical** |
| Dense network (TensorFlow, seeded, deterministic ops) | bit-identical |
| SHAP values and base values | bit-identical |
| LIME weights | bit-identical |
| Surrogate fidelity and ranking | identical |
| Event labels, detected fault start and clearing times (2 x 500 events) | identical |
| Trajectory features (165 / 67 per event, 5 windows) | identical within 6e-16 relative (summation order), except `sys_voltage_recovery_time` (D10) |

matches the reference for all 36 model/dataset combinations (0 differences).

## Defects found

Severity: **A** changes or invalidates research results, **B** wrong behaviour or
reproducibility problem, **C** robustness, security or hygiene.

| ID | Sev. | Defect (old code) | Effect | Resolution |
|---|---|---|---|---|
| D1 | B | `load_dataset(test_size=...)` split without stratification and with `random_state=None` by default; `return_X_y`/`as_frame` silently ignored with `test_size` | different split on every call; 9-bus classes are 72/28 | splitters take an explicit seed and stratify by default |
| D2 | A | models were trained on raw features (rotor angles in degrees next to voltages in p.u., column std 0.07 to 24) without scaling | distance- and gradient-based models (SVM, KNN, MLP, LR, GP) under-perform; results depend on units | `make_pipeline` puts a StandardScaler in front, fitted on training data only (leakage tests in `tests/core/test_evaluation_leakage.py`) |
| D3 | B | each classifier wrapper built its estimator in `__init__` and took `**kwargs` | `set_params` and grid search silently ignored; `clone` dropped all kwargs including `random_state`; `classes_` hard-coded to [0, 1] | registry returns plain scikit-learn estimators; unknown hyperparameters raise |
| D4 | B | `LGBMClassifier` wrapper passed `verbose` twice | crashed whenever the user passed `verbose` (failing old test) | fixed |
| D5 | B | `QuadraticDiscriminantAnalysis` with defaults | singular covariance error on **both** bundled datasets (failing old test; baseline error) | registry default `reg_param=0.01` |
| D6 | C | pretrained models were pickles downloaded from Google Drive without checksum; the bundled ones need `pycaret` (not a dependency) | arbitrary code execution on load; models unusable | skops files, SHA-256 verified, retrained with fixed seeds (`tranpy train-pretrained`) |
| D7 | B | `EnsembleClassifier` fitted every member and then `VotingClassifier` refitted clones | double training cost; Keras members not clonable | removed; use `sklearn.ensemble.VotingClassifier` over registry pipelines |
| D8 | B | explainers: LIME unseeded; LIME "global" explanation ran Submodular Pick on the training data although it required test data; surrogate "fidelity" was R² with swapped arguments on class labels; caches keyed by model class name only; `plt.show()` and files written to the working directory | non-reproducible and stale explanations; meaningless fidelity number | seeded functions returning one `Explanation` type, no caches or side effects; fidelity = agreement rate; global LIME = mean absolute weight over the explained rows |
| D9 | **A** | fault clearing time detected from voltage recovery and used as the start of the early-prediction window | for collapsing (unstable) events "clearing" is found late: median detected fault duration on New England 0.25 s (stable) vs 0.27 s with 95th percentile 2.6 s (unstable); on the 9-bus system the out-of-step flag is set *before* the detected clearing in most unstable events (median onset 0.23 s before). Windows "after clearing" therefore already contain the outcome; early-prediction accuracy is optimistic | windows need an explicit reference: `fault_start` (causal), `fault_clear` (reproduces old behaviour, documented as non-causal) or `absolute`. Simulated datasets store the true clearing time |
| D10 | A | `sys_voltage_recovery_time` returned the *absolute* simulation time of recovery (or the window end) | the feature mostly encodes the random fault start time | measured from fault inception (censored at the window end) |
| D11 | B | early prediction: AUC set to 0 for folds where it is undefined; windows with one class were still cross-validated; probability helper returned P(class 0) for models with one probability column | biased mean AUC; invalid folds | NaN excluded from means; such windows skipped; single-class models handled |
| D12 | **A** | old mock engine drew the stability label first and then generated features from label-specific distributions; out-of-step flags disagreed with the intended label; reseeded NumPy's global RNG; two seeded runs gave different labels | any result on mock data measured the generator, not a method | new mock integrates swing equations; the label follows from the dynamics; no global state |
| D13 | B | dataset generator named features `bus_1..bus_n` but ordered buses by string sort (`Bus_10` before `Bus_2`) | most generated columns mislabelled | generation keeps channel names; no renaming |
| D14 | A | PowerFactory path without CSV export took the "fault" and "clearing" snapshots from the *final* simulation state; CSV export selected generators only, so bus columns were missing; snapshot row by `ceil(t/step)` | label leakage into features; empty bus snapshots | adapter returns full trajectories of all monitored elements |
| D15 | C | load change drawn with `randint(-max, max)` (excludes +max); clearing time used a hard-coded 50 Hz | asymmetric sampling | closed interval; system frequency |
| D16 | C | three configuration systems; YAML round trip lost `random_seed` and `export_csv` | irreproducible configs | one typed loader that rejects unknown keys and reports all problems |
| D17 | C | import-time side effects: pandas shim in `sys.modules`, `~/.tranpy` created when listing models, `print`/`input()` in library code; temporal loader read `GOOGLE_API_KEY` from `.env.local` found by relative paths | surprising behaviour, secret handling | removed; downloads use a checksum-pinned registry |
| D18 | C | registry and docstrings: 78 / 18 features; data: 77 / 17; feature meaning unknown (`F_0..`) | documentation wrong | metadata corrected; semantics recorded as unknown |
| D19 | B | `RNNClassifier` reshaped `(n, f)` to `(n, n_steps, f)`, which fails for `n_steps > 1`; LSTM/TCN/Transformer fed 2-D data as sequences of length 1 | sequence models were not sequence models | `n_steps` splits each row into time steps (validated) |

## Intentional deviations (summary)

* D2 scaling inside pipelines, D9 window reference, D10 recovery time, D11 NaN AUC,
  D5 QDA regularisation, D12 new mock engine. Every other output is identical to the
  corrected reference.

## Observations kept for continuity (open decisions)

* `sys_max_relative_angle` is mathematically identical to `sys_angle_spread_max`
  (largest pairwise difference = max minus min). Kept so feature sets stay comparable.
* `find_knee_point` uses index-based derivatives, i.e. treats the windows as equally
  spaced. Kept; with derivatives over the window length the knee moves to longer windows.
* The snapshot datasets contain duplicated rows (New England 25, 9-bus 22) that can fall
  on both sides of a split. `ExperimentSpec(group_duplicates=True)` keeps them together;
  the default is unchanged.
* `SVC(probability=True)` is deprecated in scikit-learn 1.9 and removed in 1.11; the
  dependency is capped below 1.11 to keep SVM results identical.

## Performance (same machine, single run, seconds)

| Step | Old | New | Speed-up |
|---|---:|---:|---:|
| Load both snapshot datasets | 0.036 | 0.023 | 1.6x |
| Load both event datasets (2 x 500 events) | 12.0 (CSV) | 4.3 (.npz) | 2.8x |
| Trajectory features, 10 window settings | 10.0 | 2.9 | 3.5x |
| Early prediction, both systems | 12.6 | 8.1 | 1.6x |
| Fit all classical models, both systems | 35.8 | 33.0 | 1.1x |
| SHAP, 2 x 50 rows | 15.5 | 21.8 | 0.7x |

SHAP is slower because the scaler now runs inside every model call of the permutation
explainer (the price of explaining in the original feature units).

## How results stay pinned

* `tests/regression/test_snapshot.py` checks the seeded metrics of every model/dataset
  combination against `tests/snapshots/metrics.json`. After an intended change run
  `uv run python -m tests.update_snapshot` and state the reason in the commit message.
* Bundled and downloadable data files are pinned by SHA-256 in
  `src/tranpy/resources/registry.json`; `.npz` files are written byte-for-byte
  reproducibly, so re-running `scripts/convert_legacy_data.py` reproduces the checksums.
